# Pokemon TCG AI agent

Agent for the Kaggle [`pokemon-tcg-ai-battle`](https://www.kaggle.com/competitions/pokemon-tcg-ai-battle)
ladder. A submission is a tarball with a `main.py` exposing
`agent(observation) -> list[int]`. The runner calls it once with `select == None`
to get a 60 card deck, then once per selection callback.

Use `.venv/bin/python` and run everything from the repo root as a module.

## Where things stand (2026-08-08)

The two active submissions are Dunsparce ref **55339282** (about 815 after 48
episodes) and the exact frozen Tech-Grim champion ref **55335692** (about 910
after 55). The Dunsparce archive beat the champion **155-85 (64.6%)** locally at
1.1 s/move, but that result did not transfer to the public ladder. Treat it as a
failed external-validation result, not the new champion.

The previous 1127-period Lucario PPO run is also invalid as a scale result:
**85.7% of its 252,448 games were generated by stale policies** because async
rollouts crossed learner updates. It reached only 8.4% of the 3M-game lower
bound reported in the public RL discussion. The collector, PPO ratios, KL stop,
resume path, league anchor and packaging ABI are now corrected; old checkpoints
must not be resumed or submitted.

The previous champion (`harness/anchors/grpo_tech_grim_972_912_811.tar.gz`)
scored 972.0, then 911.9, then 810.8 on identical bytes, so treat any single
ladder score as worth about plus or minus 160 points.

Search is worth roughly 300 points. Every search-free submission we have made
scored between 480 and 591.

## The rules that matter

**1. Gate against the anchors, never against ourselves.** `harness/anchors/`
holds packaged tarballs named for the ladder score each one actually earned.
Every serious mistake in this project came from comparing our own components to
each other, which can look great while the whole family sits below a baseline
nobody tested.

**2. Gate at 1.1 seconds per move.** A cheap harness run does not just add noise,
it inverts the answer. At 0.1 s/move the harness ranked our worst agent (real
score 480) above our best (810 to 972) by 7-1. At 1.1 s/move the same two go
10-0 the correct way. A small budget starves search and leaves a search free
agent untouched.

**3. Move the deck and the prior together.** They are not independent axes.
`tools/score_by_deck.py` shows the old champion scoring 79.5% top-1 on Tech-Grim
decisions and roughly 50%, i.e. chance, on every other deck. So a deck swap
under it measures the prior's blind spot, and a prior change on its own deck is
confined to a deck that wins 47.9% against the field. Five careful prior-only
experiments all landed 39-53%; changing both at once produced 64.6%.

**4. Rank decks by field-weighted win rate.** `tools/matchup_matrix.py` computes
`sum over opponents of share(opp) * winrate(vs opp)` from real replays, which is
what a ladder score pays. Raw win rate hid an 8-point understatement on the deck
we now ship. Also discount by mean pilot Elo: Mega Lucario's 67.3% raw win rate
comes from pilots averaging 1224, and under our pilot it gated at 48.8%.

## Measuring

```bash
.venv/bin/python tools/ladder_harness.py \
  --archives harness/anchors/*.tar.gz artifacts/<candidate>.tar.gz \
  --games-per-pair 20 --budget 1.1 --workers 10 --calibrate
```

Plays real tarballs against each other through `kaggle_environments.make("cabt")`,
the same environment that scores the competition, and fits Bradley-Terry ratings.
`--calibrate` regresses those against the anchors' known scores and prints the
rank correlation, so you can see whether the harness reproduces an ordering we
already know before trusting it on one we do not. Details in `harness/README.md`.

Do not run other heavy jobs at the same time. Workers are pinned to one thread
each so per move budgets stay comparable across matches.

## Building a submission

```bash
.venv/bin/python -m rl_osfp.build_bcsearch_submission \
  --model rl_osfp/run_v3/model_period_180.npz \
  --deck-csv foundation/deck_tech_grim.csv \
  --out artifacts/submission_x.tar.gz

.venv/bin/python -m rl_osfp.verify_bcsearch_submission --archive artifacts/submission_x.tar.gz
```

`foundation/search_shell_main.py` is the frozen `main.py` that scored 972. It is
byte identical across all three of our best archives and is never edited. The
builder refuses to run if its md5 changes. To put a different network behind it,
swap the files around it, not the shell.

**Always verify.** The shell catches network errors and quietly falls back to
heuristic priors, so a dead checkpoint still produces a well formed archive that
plays legal games at normal latency. The verifier asserts the priors actually
fire.

## Layout

```
bc_train/      behaviour cloning, SEQ 53 encoders (the width the shell serves)
  ingest_episodes.py   raw episode dumps -> shards, parallel, bounded memory
  train_bc.py          the trainer
rl_osfp/       PPO inside optimistic fictitious play
  train.py     synchronized PPO + frozen prior/historical opponent league
  audit_run.py hard scale/readiness gate (lag, continuity, pool, errors, KL)
  rollout.py   synchronized, reusable process-level worker pool
  build_bcsearch_submission.py / verify_bcsearch_submission.py
foundation/    engine bindings, encoders, and the frozen search shell
  cg/          official native engine, licensed, gitignored, never commit
harness/       anchors with known ladder scores, plus reports
  meta/        deck census and matchup matrix from the replay dumps
tools/         harness, deck mining, pool building, corpus tools
data/fresh/    deck pool and the replay and leaderboard archives behind it
```

## Training a prior from scratch

```bash
# 1. raw dumps -> elite shards (refresh the official data first)
.venv/bin/python bc_train/ingest_episodes.py data/fresh/replays \
  --out data/bc_elite_aug --leaderboard data/fresh/leaderboard/*.zip \
  --min-elo 1000 --features rich --workers 6

# 2. cap every deck so no list dominates; hold out a whole day
.venv/bin/python tools/balance_corpus.py --data data/bc_elite_aug \
  --out data/bc_bal --holdout-day 2026-08-06 \
  --holdout-out data/bc_bal_holdout --cap-per-deck 60000

# 3. train from random init, then check it per deck, not just overall
OMP_NUM_THREADS=6 PYTHONPATH=bc_train .venv/bin/python -u bc_train/train_bc.py \
  --data data/bc_bal --val-data data/bc_bal_val --max-per-shard 23000 \
  --dim 160 --layers 5 --heads 5 --features rich --elo-weight 0.5 \
  --epochs 14 --patience 3 --device cuda --out data/model_new.npz

.venv/bin/python tools/score_by_deck.py --data data/bc_bal_holdout \
  --models champion=data/model_champion_bc.npz new=data/model_new.npz \
  --decks lucario=11400519690197900657 dunsparce=5201313099195159999

# 4. package once per candidate deck, verify each, gauntlet vs the champion
bash tools/deck_arms.sh data/model_new.npz mytag 80 8
```

Run `tools/resource_guard.py --data <dir>` first. It refused 1,068,344 rows
(18.9 GiB peak) and is not advisory: ignoring it killed this machine's VM twice.
Always redirect training through `python -u`; block buffering hides the epoch
lines for tens of minutes and looks exactly like a hang.

## RL training and scale gate

PPO is on-policy. Recording `old_logp` corrects the action likelihood ratio; it
does **not** correct the stale state distribution created when an old policy
keeps playing through a learner update. The old 29 games/s async measurement
was therefore not a free throughput gain. `--async-rollout` is deprecated and
now runs synchronously. Use an actor-lag algorithm such as V-trace before ever
allowing updates and collection to overlap again.

Start with a short correctness/learning gate under the exact shipping encoder:

```bash
PTCG_MAX_OPT=24 .venv/bin/python -u -m rl_osfp.train \
  --pool data/fresh/deck_pool_20260808_broad_lucario.json \
  --init data/model_lucario_scratch.npz \
  --out-dir rl_osfp/run_clean_gate --periods 12 \
  --games-per-period 96 --max-decisions 14000 \
  --epochs 2 --lr 7e-5 --target-kl 0.02 --ref-kl-coef 0.2 \
  --workers 10 --threads 4 --device cuda --max-wall-minutes 90

PTCG_MAX_OPT=24 .venv/bin/python -m rl_osfp.audit_run \
  rl_osfp/run_clean_gate --strict
```

The audit must show zero policy lag, engine errors and invalid actions before a
long run. Then gate multiple checkpoints both standalone and behind the frozen
search shell. Scale only if those curves improve; the target is at least 3M
games, not another 250k-game run. The default learning rate decays to 10% across
the declared periods, and CUDA allocation is capped at 72% of VRAM.

The exact two-arm gate/resume commands, go/no-go criteria and safe Kaggle slot
order are in `RL_AUDIT_AND_TOMORROW_PLAN.md`; the executable entry point is
`bash tools/run_rl_tomorrow.sh gate {techgrim|lucario}`.

## Gotchas that cost real submissions

- The runner execs `main.py` as a string, so `__file__` is undefined, and it
  pops the agent dir off `sys.path` before `agent()` is called. It also takes
  the **last** callable defined in the module.
- `cabt` awards the game to the opponent on any rejected `select`, with no
  retry. Validate index range, duplicates, and min and max count.
- Never ship `cg/__pycache__`. A stray 3.12 `.pyc` failed episode validation.
- Read the per move budget from `remainingOverageTime`. Do not hardcode it.
- Step caps are not errors. Counting them as errors rewards stalling, because a
  policy that refuses to commit gets its stalls deleted from the denominator.
- `train.py` only ever pilots `learner_decks` and only ever faces `field_decks`.
  A deck listed only in the field is one the policy has never played.
- Never use `rl_osfp/run_lucario` as an init or resume source. Run
  `rl_osfp.audit_run --strict` before trusting any training directory.
